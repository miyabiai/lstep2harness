# lstep2harness

Lステップのデータを公式APIから取り出し、必要に応じて利用者がログインした管理画面から設定を補って、L Harness（[line-harness-oss](https://github.com/Shudesu/line-harness-oss)）へ移すツールです。セットアップ済みの L Harness（Cloudflare の D1）へ直接入れ、入れた全行を照合します。切り替えまで Lステップと並行で動かすためのブリッジも入っています。

> **現在、管理画面だけの取得は使えません。** 管理画面の応答に友だちの LINE ユーザーID が含まれないため、この経路だけでは友だちを移せません。このツールは表示名では照合しません。`--route browser` はログイン後に1人分を確かめ、LINE ユーザーID が無ければ止まり、L Harness には何も入れません。公式APIで LINE ユーザーID を取得し、管理画面から設定を補う `--route hybrid` は別の経路です。使い方と制限は下の「公式APIと管理画面を組み合わせる」を見てください。[管理画面の再確認結果](docs/verification.md#管理画面からの取得の再確認2026-11-04)

> **公式API単独の経路は実機確認済みです。** プロプラン以上と API 連携オプションを利用し、少数のテストデータで UID取得→隔離した試験用DBへの移行→照合→再投入まで確認しました。この経路だけではテンプレート本文・シナリオなどのAPI対象外データは移せません。[公式APIの実機検証と残る制限](docs/verification.md#公式apiの実機試験2026-11-04)を見てください。

> **組み合わせ取得（hybrid）も実機確認済みです。** 少数のテストデータで、公式APIの友だち情報・会話を保ったまま文字テンプレート・シナリオの本文とステップ・基本的なフォーム設問を補い、隔離した試験用DBへの移行・照合・再投入を確認しました。Flex、空でないフォーム回答の実移行、配信方式・日時や進行の完全再現は確認できていません。全設定の完全移行・本番での配信再開を保証する結果ではありません。[確認範囲と制限](docs/verification.md#組み合わせ取得hybridの範囲)

このREADMEのシナリオ・フォームに関する移行の説明は、`hybrid` で対応する設定を取得する場合、または過去に管理画面から取得済みのデータを扱う場合のものです。公式API単独で移せる範囲は「[取得できる範囲と移し先](#取得できる範囲と移し先)」の公式API列を確認してください。

- 投入の前に、取れた件数・移せないもの・移行先の今の状態をチャットで伝え、利用者の「移行して」を待ちます
- 新しく移すシナリオ・フォームは**停止のまま**入れるので、移行しただけで L Harness から送り始めることはありません（L Harness で有効にした後の扱いは下の「並行運用」「切り替え」）
- L Harness に元からいる友だちは、表示名・アイコン・L Harness 側の情報を変えず、Lステップの情報・タグ・会話を足します
- 移行し直しても、L Harness で有効にしたシナリオ・フォームを止めず、有効にした後の配信の進み具合も上書きしません。有効にしたシナリオに新しく入る人は「一時停止」で入れ（自動では送りません）、そのシナリオの設定・ステップは足しも書き換えもしません（Lステップで消したステップが残っていれば、件数を知らせます）。停止中のシナリオは Lステップの今のステップに揃えます（消したステップは消えます）
- 移行し直しても、L Harness で人が直したもの（友だち情報の値・チャットの対応状態（未読・対応済み）・メモ）は変えません。このツールが入れたままの友だち情報だけを Lステップの新しい値にし、Lステップの最新の値はいつも `_lstep` に残します。フォームの回答数は、L Harness が受けた回答も含めて数え直します
- 作成済みの移行計画は繰り返し投入できます。投入が途中で止まった場合も、同じ計画の `apply` で続きから流せます。API取得が中断した場合は、新しく取得し直してください

> **非公式ツールです。** 「Lステップ」は提供元（ソーシャルデータバンク株式会社、旧 株式会社Maneql）の商品名で、その商標は提供元のものです。「LINE」は LINEヤフー株式会社の、「Cloudflare」は Cloudflare, Inc. の商標または登録商標です。このツールは提供元・L Harness の開発元とは関係がなく、提供元が認めたものでもありません。npm には公開していません。

[実利用テストの結果と残る制限](docs/user-test-2026-10-29.md)

## 使い方（AI に任せる）

Claude Code か Codex でこのフォルダを開き、チャットで次のように頼むだけです。コマンドを自分で打つ必要はありません。

> README の手順でセットアップして、Lステップのデータを L Harness に移行して

AI は [AGENTS.md](AGENTS.md) の手順で進めます（Claude Code は [CLAUDE.md](CLAUDE.md) から同じ内容を読みます）。人がするのは次のことだけです。

| いつ | すること |
|---|---|
| 最初に1回 | Cloudflare へのログイン（L Harness を入れたアカウント。ブラウザが開きます。ログイン済みなら不要） |
| 最初に1回 | `.env` を開いて、L Harness の API キーを貼る（値はチャットに書きません） |
| 公式APIで取得するとき | Lステップの「API連携→認証」で取得したトークンを、`.env` の `LSTEP_API_TOKEN` に本人が保存する（値はチャットに書きません） |
| 管理画面の設定も補うとき | 内部の読み取り口を使ってよいか AI に返事をし、取得専用の Chrome で、APIと同じLステップアカウントにログイン（`--route hybrid`。APIトークンも必要） |
| 投入の前 | AI が伝える件数・移せないもの・移行先を見て「移行して」と返す |

操作で迷ったら、[人が行う操作の案内](docs/tutorials/README.md)を開いてください。LINE の ID・シークレット・トークンの取得、LINE ログイン、LIFF、Cloudflare、値の保存、Lステップへのログインを章ごとに案内します。収録済みの動画と準備中の章は、一覧で区別しています。

流れはこうです。

1. AI が部品を取り込み、L Harness の導入フォルダ（create-line-harness の既定は `~/.line-harness`。中の `.line-harness-config.json` か `apps/worker/wrangler.toml`）からつなぎ先を読みます（`connect`。L Harness には書き込まず、このフォルダに設定ファイル `lstep2harness.config.json` と `.env` の空欄を作ります）。別の場所に入れたときは、頼むときに場所を伝えてください
2. AI が Lステップから取り出し、移行計画を作ります（`migrate --harness`。設定も補う場合は `--route hybrid`。まだ投入しません）
3. AI が「取れた件数」「移せないもの・その理由」「移行先のアカウント名・今いる友だち・重なる人数」を伝えます
4. 「移行して」と返すと、AI が L Harness へ入れて、全行を照合した結果を伝えます
5. LINE に登録済みのリッチメニューを L Harness の管理画面に取り込み（`richmenu`）、アイコン・表示名を LINE から取り直します（`enrich`）
6. 切り替えまで並行で動かすなら、ブリッジを用意します（`bridge`。下の「並行運用」）

まず試したいときは、本番の代わりに手元の試験用データベースへ移すこともできます（下の「試験用データベースで試す」）。

## 必要なもの

| もの | 備考 |
|---|---|
| Node.js 22.13 以上 | `node -v` で確認（`node:sqlite` を使います） |
| セットアップ済みの L Harness | `npx create-line-harness` を最後まで終えていること |
| L Harness の API キー | セットアップ完了画面の「API Key」。リッチメニューの取り込み・アイコンの取り直しに使います |
| Lステップの API トークン | プロプラン以上と API 連携オプションが必要。「API連携→認証」のトークンを `.env` の `LSTEP_API_TOKEN` に本人が保存します |
| Cloudflare へのログイン | `npx wrangler@4.150.0 login`（L Harness と同じアカウント）。または `.env` に `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` |
| Google Chrome | `--route hybrid` で管理画面の設定も補う場合など（このツールは Chrome を入れません） |

L Harness をこれから新しく用意する場合は、[LINE の接続情報](docs/tutorials/index.html#line-messaging-api)・[LINE ログイン](docs/tutorials/index.html#line-login)・[LIFF](docs/tutorials/index.html#liff)・[Cloudflare](docs/tutorials/index.html#cloudflare-account)の案内を使えます。L Harness の作成そのものは、開発元のセットアップ手順で進めます。

Lステップと L Harness は、**同じ LINE 公式アカウント**（同じ Messaging API チャネル）につないでいる必要があります。違うチャネルに移すと、友だちに送れません。

## 本番に入れるときの安全策

投入中（SQL ファイルを D1 へ取り込んでいる間）は、L Harness のデータベースが一時的に応答しにくくなり、管理画面や LINE からの受信の処理が失敗することがあります。友だちの出入りが少ない時間帯に行ってください。

動いている L Harness へは、試験用データベースのように「1つのまとまりで入れて、失敗したら全部取り消す」ことができません（D1 には全ファイルをまたぐ取り消しが無く、L Harness が同時に会話を受けています）。代わりに次の順で守ります。

1. **書き込む前に、読み出しだけで確かめる。** 移行先アカウントがあるか、L Harness の表の形がこのツールの想定どおりか、計画を作った後に友だち・同じ名前のタグが増えていないか、前回入れた取得結果より古くないか。どれかが合わなければ、本番に触れずに止まります（計画の作り直しのコマンドを出します）
2. **手元で試し流しする。** 同梱の L Harness のスキーマで作った手元のデータベースに全 SQL を流し、通らなければ本番に触れません
3. **投入前の状態のしおりを残す。** D1 の Time Travel（無料プランは7日・有料プランは30日以内の時点に戻せる機能）のしおりを `bookmark.txt` に残します。自動では戻しません（戻すと、投入中に L Harness が受けた会話も消えるため）
4. **途中で止まっても続きから。** SQL は何度流しても同じ結果になる形です。止まったら同じ `apply` をもう一度実行すると、流し済みのファイルを飛ばして続きから流します
5. **全行を照合する。** 入れた全予定行を読み出して内容を照らし合わせ、合ったら移行記録を「完了」にします

どの取得結果を移したかは、L Harness のデータベースに `lstep2harness_applied` という表を1つ作って記録します（L Harness 本体は使いません）。取得し直した新しい結果は、同じ移行先に重ねて入れられます（増えた分が足されます）。

## 取得できる範囲と移し先

| データ | 公式API | 管理画面（hybridの設定補完・過去の取得範囲） | L Harness での行き先 |
|---|---|---|---|
| 友だちのLINEユーザーID・名前・ブロック | 対応 | 現在はLINEユーザーIDを取得できません（上のお知らせ） | 友だち |
| タグ・友だち情報の定義 | 対応 | 対応 | タグ・友だちのメタデータ |
| 友だちごとのタグ・情報の値 | 対応（100項目ごとに分けて取得） | 対応 | タグ付け・メタデータ |
| 会話 | 対応形式のみ。システム通知は除外 | 文字中心。画像等はURLのみ。システム通知は除外 | チャット画面 |
| テンプレート | 一覧のみ（本文は対象外） | 文字本文。Flex・画像などは未対応 | テンプレート |
| シナリオ | 対象外 | 文字・テンプレート参照・タグ追加を中心に対応。配信方式・日時の再現は未検証 | シナリオ（停止のまま） |
| 回答フォーム | 指定フォームの回答のみ（設問は対象外。設問が無いので移行先には入れず、取得結果に保存するだけ） | 基本的な設問・回答 | フォーム（停止のまま）・回答（管理画面から取得したときだけ） |
| 流入経路 | ID・名前のみ保存（移行先には作らない） | 未対応 | ― |
| リッチメニュー | ― | ― | LINE に登録済みのメニューを `richmenu` で管理画面に取り込み |
| 自動応答・あいさつ | 未対応 | 未対応 | ― |

「対応」はすべてのアカウント・機能で動く保証ではありません。取れなかったもの・移せないものは `migrate` の表示と `report.md` に出ます。画像・ファイルは取得元の URL を参照しているので、Lステップを解約する前に、必要なものは L Harness の管理画面で登録し直してください。実際に確かめた範囲は [検証の状況](docs/verification.md) にあります。

## 公式APIと管理画面を組み合わせる（hybrid）

公式APIの友だち情報を使い、テンプレート本文・シナリオ・フォームの設定を管理画面から補う場合は、明示的に指定します。既定の `auto` は公式APIだけを使います。

```sh
node dist/cli.js migrate --harness --route hybrid
# 試験用DBでは --harness の代わりに --db <新しい試験用DB> --line-account-id trial
```

`LSTEP_API_TOKEN` を本人が `.env` に保存したうえで実行し、開いた取得専用 Chrome で**APIと同じLステップアカウント**にログインしてください。管理画面の補完は、提供元が公開していない内部の読み取り口を使います。「ご利用にあたって」を確認し、AIに任せる場合も利用者の了解を得て実行します。取得は読み取りだけで、1.1秒以上の間隔を空けます。

公式APIから取得したトークン・LINEユーザーIDはブラウザへ渡しません。数値の友だち管理番号を使い、通常の友だち一覧と詳細応答がAPIの友だちに一致するかを確認してから結びます。画面側にもLINEユーザーIDが返る場合は、Node側で完全一致を確認します。表示名では照合せず、不一致・未知の管理番号・重複があれば停止します。

友だち全員・表示名・タグ・情報値・会話・対応状態は公式APIの結果を保持します。管理画面から採用するのは、対応する文字テンプレート、シナリオの本文・ステップ・タグ追加、基本的なフォーム設問と回答、解釈できる購読状況です。テンプレートは明示された種類が文字（`form_type: 8`）のものを扱い、Flex・画像の説明文を文字本文として移しません。未取得・未対応の設定は表示と `report.md` に残ります。

**配信の自動再開は保証しません。** 管理画面の購読状況を解釈できない場合は未取得として扱い、進行位置や次の配信時刻を推測しません。購読は取得できても何通目かを復元できない人は、一時停止・進行位置不明・次回配信なしで入ります。内部項目 `date_diff` の意味を確認できておらず、配信方式・日時（時刻指定・経過時間を含む）の再現全体は未検証です。本文・ステップを含む新しいシナリオとフォームは停止状態で入ります。再開前に、L Harnessで本文・対象・配信方式・配信日時を確認し、配信方式・日時を再設定してください。

友だちごとの購読状況の補完は最大1,000人です。上限や取得中断があっても、公式APIで取得した友だちを削ったり、未取得の購読状況を全件取得済みにしたりしません。ブラウザ側の補完には別のページ数・取得回数・時間の上限もあり、不足は一部取得または失敗として扱います。

## 公式APIの呼び出し回数

友だちと会話は、それぞれ最大1,000件ずつページ送りして取得します。会話は全体を取得して友だちのID・UIDで振り分けるため、会話の有無を1人ずつ問い合わせません。タグ・友だち情報の定義が100項目を超える場合も、100項目ごとに友だち一覧を読み直し、個別の詳細取得を避けます。

5万人を超える架空データの試験で、取得本体の呼び出し回数と全データの保持を確認しています。[条件と結果](docs/verification.md#大量データの取得回数合成試験)を見てください。実際の回数は、友だち数に加えて会話の総数・属性数・指定フォームの回答数・再試行によって増えます。契約の月間上限と残り枠を確認して実行してください。

友だちのID・UIDの不一致、追加属性の取得漏れ、友だち一覧にない会話などは、欠落を成功扱いにせず停止します。取得中に対象が変わった場合も、内容を確認してから新しく取得し直してください。

API取得が中断した場合、取得途中のページからの再開には対応していません。取得は新しくやり直し、残りの利用枠を確認してください。作成済みの移行計画の投入は、同じ計画で再実行できます。

## 並行運用（bridge）

LINE の Webhook URL は1つしか設定できません。切り替えまでの間は、Lステップの **「Webhook転送」**（Lステップのオプション機能。2026年10月時点で月額 5,500円。[提供元の料金ページ](https://linestep.jp/lp/01/plan.html)では「LINE のイベント（追加・受信など）や回答フォームの回答」を外部へ即時送信するとあります）で、L Harness にも同じ出来事（友だち追加・ブロック・メッセージ・ポストバック）を流します。実際にどの形で届くかは契約して確かめていません（[検証の状況](docs/verification.md)）。ブリッジは LINE の Webhook の形で届いたものだけを L Harness に渡し、それ以外（フォームの回答など）は受け取っても渡しません。

```sh
node dist/cli.js bridge --deploy
```

- Cloudflare に小さな Worker（ブリッジ）を配備し、LINE のチャネルシークレットで署名を付け直して L Harness の `/webhook` に渡します。`.env` に `LINE_CHANNEL_SECRET` が要ります
- 転送先 URL は `.lstep2harness/bridge-url.txt` に出ます。Lステップの「Webhook転送」に貼って有効にしてください。**URL は人に見せないでください**（末尾のトークンが鍵です。漏れたら `bridge --deploy --rotate-token` で同じ Worker のトークンを入れ替えると、前の URL は使えなくなります。新しい URL を Lステップに貼り直してください）
- 要らなくなったブリッジ（別のフォルダで作った古いものなど）は、Cloudflare の管理画面の Workers で削除してください。消さない限り、その URL は受け付け続けます
- このツールを更新したら、もう一度 `bridge --deploy` を実行してください。`bridge/` の Worker のソースは毎回、同梱の版に揃えてから配備します（転送先 URL・重複排除の設定はそのままです）
- 転送に署名（`X-Line-Signature`）が付いていれば検証し、合わないものは断ります。10分より古い出来事は捨てます
- replyToken は Lステップが先に使うので外して渡します
- L Harness へ渡せたときだけ受け取ったと返し、渡せなければ失敗（502）を返します。同じ出来事が二重に届くのを防ぐ重複排除（Cloudflare KV）は既定では付けていません（`bridge/wrangler.toml.example` を参照。付けた設定は配備し直しても残します）。重複排除を付けても、同じ出来事がほぼ同時に2回届いたときは防げません
- ブリッジの Worker 名はフォルダごとに変えます（`lstep2harness-bridge-<英数字>`）。別の L Harness・アカウントへ移すときは、別のフォルダで用意してください（同じフォルダで別の移行先へ配備し直そうとすると止めます）
- `wrangler login` で配備したときは、転送先 URL を `wrangler deploy` の表示から作ります。作れなかったときはファイルに「サブドメインを置き換えてください」と出ます
- 並行運用中に L Harness が自分で記録した会話は、あとで移行し直しても二重に入れません（同じ向き・同じ本文で、時刻の差が10分以内のもの。この条件に当たる別の会話も1件ずつ同じものとみなします）
- **Lステップの転送にタグや友だち情報の変更は入りません。** 並行運用中に Lステップで付けたタグは、切り替えの直前にもう一度移行すると反映されます
- L Harness で動いているシナリオ・自動応答・オートメーションがあると、二重送信を防ぐため配備を止めます（承知のうえなら `--accept-active`）。L Harness が最初から入れている「マイル」の自動応答は数えません

並行運用中に **L Harness でやってはいけないこと**：シナリオ・自動返信を有効にする（Lステップと二重に送られます）／取り込んだリッチメニューで「公開」「公開停止」を押す（LINE 上のメニューが作り直され、Lステップが人ごとに出しているメニューが外れます）。

### 切り替え

ステップ配信の予定が入っていない時間帯に、続けて行ってください。

1. もう一度 `migrate --harness`（設定も補う場合は `--route hybrid`）→ 投入（再取得した範囲のタグ・友だち情報・会話が反映されます。公式API単独ではシナリオ・フォーム等は更新されません。復元できない配信進行は自動再開しません）
2. Lステップでシナリオ・自動応答を止める
3. LINE Developers コンソールで Webhook URL を L Harness の `/webhook` に変え、Lステップの Webhook転送を無効にする
4. L Harnessで内容・対象・配信方式・日時を確認し、必要な再設定を済ませてからシナリオ・自動返信を有効にする
5. Lステップで設定していた「誰にどのリッチメニューを出すか」を L Harness の自動化で作り直す

移行し直しても、Lステップで外したタグ・消した友だち情報は L Harness から消しません（足すだけです）。外したものは L Harness の管理画面で外してください。L Harness で直した友だち情報の値はそのままです（Lステップの最新の値は友だちのメタデータの `_lstep.friend_info` で見られます）。逆に、L Harness で**消した**タグ付け・友だち情報の項目は、Lステップにまだあれば移行し直しで戻ります（消すのではなく値を変えておくと戻りません）。

停止中のシナリオのステップは、移行し直すたびに Lステップの今の内容に揃えます（このツールが入れたステップを入れ直し、Lステップで消したものは消します）。L Harness の管理画面で手で足したステップがある停止中のシナリオは、並びが重なるので投入前に止めて案内します（足したステップを消すか、そのシナリオを有効にしてください。有効なシナリオは変えません）。

移行し直したときに何が変わるかの一覧です。

| 扱い | 対象 |
|---|---|
| Lステップの今の内容に揃える | タグ名・テンプレートの本文・停止中のシナリオ（名前・ステップ。`hybrid` の配信方式・日時の再現は未検証）・フォームの設問とお礼の文（L Harness で有効にしたフォームも）・友だちの `_lstep`・このツールが入れたままの友だち情報の値・対応ステータス（タグ・メモ）・復元できる停止中のシナリオの進み具合 |
| L Harness 側のまま変えない | 表示名・アイコン・ブロック状態（初回に入れた後は `enrich` やブリッジで更新）・L Harness で直した友だち情報の値・チャットの対応状態と人が書いたメモ・有効にしたシナリオの全部・L Harness 自身が作ったステップ配信の進行状態・各行の更新日時（L Harness 側の方が新しいとき） |
| 足すだけで消さない | Lステップで消したシナリオ・テンプレート・フォーム・回答・友だち、外したタグ、消した友だち情報の項目（L Harness の管理画面で消してください）。取れていない・未対応の設問があるフォームの設問（移行先に前からあるもの） |

取得結果に対応ステータスが含まれないとき（取得範囲から外れた場合など）に移行し直すと、このツールが書いた「対応ステータス: …」のメモは空になります（人が書いたメモは残ります）。

このツールが入れた行は ID が UUID v5（15文字目が `5`）で、L Harness 自身が作る行（UUID v4）と見分けています。ID の作り方を変えた L Harness の改造版では、この見分けが効きません。

### D1 の無料枠について

Cloudflare D1 の無料枠は **1日 10万行の書き込み**（UTC 0時＝日本時間 9時にリセット）です。友だち数千人の移行は会話履歴・タグ付けで数十万行になることがあり、上限に達すると `apply` や `enrich` が途中で止まります。翌日 9時以降に同じコマンドで続きから流すか、Workers 有料プラン（月 5ドル）にしてください。

## 試験用データベースで試す

本番の代わりに、L Harness と同じ形の手元のデータベース（停止中の移行先アカウントが1つだけ）へ移して確かめられます。本番には何も書き込みません。

```sh
npm ci                                  # 部品の取り込み。ビルドも自動で行います
node dist/cli.js init-db --db ./data/test.sqlite --line-account-id trial
node dist/cli.js migrate --db ./data/test.sqlite --line-account-id trial
# 表示された内容と report.md を確認してから、表示された next のコマンドで投入・照合
```

試験用データベースへの投入は1つのまとまりで行い、照合に失敗したら全部取り消します。停止中（`is_active=0`）で友だちが入っていない移行先アカウントにしか入れません。

## 自分でコマンドを打つ場合

```sh
npm ci
npx wrangler@4.150.0 login                           # L Harness と同じ Cloudflare アカウント
node dist/cli.js connect                             # つなぎ先を lstep2harness.config.json に保存（.env に空の欄を足す）
node dist/cli.js guide                               # 人が行う操作の案内ページの場所を表示
node dist/cli.js migrate --harness                   # 取得して計画まで。投入はしない
node dist/cli.js migrate --harness --route hybrid    # 公式APIの友だち情報に、管理画面の設定を補う
node dist/cli.js apply --out <計画のフォルダ> --harness --allow-partial   # 表示された next のとおり
node dist/cli.js richmenu --dry-run                  # 取り込むメニューの確認 → --dry-run を外して取り込み
node dist/cli.js enrich                              # アイコン・表示名を LINE から取り直す
node dist/cli.js bridge --deploy                     # 並行運用するとき
```

- `connect` は L Harness の導入フォルダ（`~/.line-harness` など）を探し、D1 の名前・Worker の URL を読みます。見つからなければ `--harness-dir <フォルダ>`、または `--d1 <D1の名前> --harness-url <Worker の URL>` で指定します（導入フォルダと違う移行先を指定したときは、導入フォルダの ID・アカウントは使いません）。アカウントが複数あるときは `--line-account-id` で選びます。API キーの確認では、URL の先の L Harness に選んだアカウントがあるかも確かめます（無ければ `mismatch`。URL とデータベースが別の導入先です）
- `hybrid` で設定を補う場合や過去に管理画面から取得済みのデータで、中身を取れなかったシナリオ・フォームは移さず、移行先に前から入っているものも変えません（`report.md` に出ます）。設定を取得し直す場合も、公式APIと組み合わせる `hybrid` が必要です
- `migrate` は取得して移行計画（SQL・照合の基準・`report.md`）を作るところまで進み、**投入はしません**。確認なしで投入まで進めるときは `--yes`（移せないものがあるときは `--allow-partial` も）を付けます
- **取得の基本は公式APIです。** 既定の `auto` は、環境変数か起動した場所の `.env` に `LSTEP_API_TOKEN` があるとき、ブラウザを開かずにAPIで取得します。設定も補う場合だけ `--route hybrid` を付けます。APIにはLステップのプロプラン以上とAPI連携オプションが必要です（[提供元の料金ページ](https://linestep.jp/lp/01/plan.html)）（[公式資料](https://docs.lineml.jp/)）。このツールから契約はしません。トークンが無い場合や、設定したAPIを使えない場合は止まり、勝手に管理画面からの取得へ切り替えません
- Windows では、本番の L Harness へつなぐ操作（`connect`・`--harness`・`bridge`）は動きません（wrangler をコマンドプロンプト経由でしか起動できず、顧客データを含む SQL がコマンド行で解釈されうるため）。WSL（Windows 上の Linux）で動かしてください。手元の試験用データベースへの移行は使えますが、Windows での動作は確かめていません
- **管理画面だけの取得経路は、現在は移行に使えません。** `--route browser` を明示して実行した場合は取得専用のChromeが開き、ログイン後に1人分を確かめます。LINEユーザーIDが無ければ、取得・移行を進めずに止まります。`hybrid` にはAPIトークンも必要です。Chromeは取得専用で、普段のChromeのCookieやログイン情報は読みません。画像認証・SMS認証も利用者が行います。ログインを15分待ちます（`--login-timeout` で変更）。途中で止めるときはCtrl+C（Chromeも閉じます）。Chromeはツールを動かしているパソコンの画面に開きます。AIの安全制限（サンドボックス）の中では起動できないことがあり、そのときはAIが「制限の外で実行してよいか」を聞きます
- `extract` は `api` と取得済みJSONの `browser` 読み込み用です。組み合わせ取得には `migrate --route hybrid` を使ってください
- 取得した内容と移行計画は、ツール専用の場所の `runs/run-…` に取得ごとに保存します（macOS・Linux ではフォルダ 0700・ファイル 0600。Windows ではこの権限を設定できないため、保存先フォルダのアクセス権をご自身で確認してください）。保存先は `LSTEP2HARNESS_DATA_DIR`（ツール専用の絶対パス）で変えられます。指定しないときは OS のアプリ用データ領域（macOS は `~/Library/Application Support/lstep2harness`）です。保存した記録は自動では消しません
- 投入・照合の SQL（LINEユーザーID・タグ名などを含む）は、実行した利用者だけが読める一時ファイルで wrangler に渡し、終わったら消します。wrangler 自身のログファイル（照合で読み出した顧客データが入る）は書かないよう指定しています
- wrangler は、手元に無ければ版を固定して `npx wrangler@<版>` で起動します。起動のしかたは `LSTEP2HARNESS_WRANGLER`（例: 複数の Cloudflare アカウントを切り替える自前のコマンド）で変えられます
- 秘密の値（`LSTEP_API_TOKEN`・`HARNESS_API_KEY`・`LINE_CHANNEL_SECRET`・Cloudflare のトークン）は `.env` に置きます。`.env`・`lstep2harness.config.json`・`.lstep2harness/` は人に渡さないでください

### プロフィール更新後にもう一度照合する

`enrich` は LINE から表示名・画像・ステータスメッセージを取り直し、更新日時も変えます。通常の `verify` は移行計画の値と厳密に比べるため、この更新後は差分を検出することがあります。

プロフィール更新を行ったことが分かっている場合は、次で4項目だけを別枠として報告できます。友だち情報・タグ・会話本文などの照合は続けます。`profileUpdates` に対象項目数と差分の列名・件数を出し、値や友だちのIDは表示しません。この指定だけで現在のプロフィールの正しさを証明するものではありません。

```sh
node dist/cli.js verify --out <計画のフォルダ> --harness --allow-profile-updates
# 同じ計画の投入を続行するときも、プロフィール更新後なら明示できます
node dist/cli.js apply --out <計画のフォルダ> --harness --allow-partial --allow-profile-updates
```

最初の投入・照合は、通常の厳密照合を使ってください。プロフィール更新の許容は `--harness` 専用で、指定しなければ従来どおり差分で停止します。

## 取得したデータの扱い

- 取得結果（`runs/run-…`）・移行計画の SQL・`bookmark.txt` には、お客さんの名前・LINEユーザーID・会話・回答が入ります。このツールは自動では消しません。移行と確認が終わったら、保存先のフォルダ（上の「保存先」）を利用者が消してください
- 移すデータは、利用者が Lステップで管理しているお客さんの情報です。移す権限・必要な同意（プライバシーポリシーでの説明など）は利用者が確かめてください。LINE 公式アカウントの利用者情報は、そのアカウントの運営に必要な範囲でだけ使え、第三者への開示・提供には LINE の書面による事前の許諾が要ります（[LINE公式アカウント利用規約](https://terms2.line.me/official_account_terms_jp?lang=ja&country=JP) 8条2項。L Harness は利用者自身が運用する環境ですが、クラウド（Cloudflare）に置くことがこの規約上どう扱われるかは利用者が確かめてください）。LINE 公式アカウントの契約が終わったときは直ちに廃棄する決まりです（同 8条5項。Lステップの解約とは別です）。利用者情報の保存・委託・削除の条件は [LINE ユーザーデータポリシー](https://terms2.line.me/LINE_Developers_user_data_policy?lang=ja) も確かめてください
- お客さんから削除を頼まれたときは、L Harness の管理画面で消し、このツールの保存先に残っている取得結果・計画も消してください
