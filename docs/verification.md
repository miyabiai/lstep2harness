# 検証の状況

確かめたことと、まだ確かめていないことを分けて書きます。合成データの試験に通ったことを、実データの移行に成功したとは書きません。

## 自動試験（合成データ）

`npm ci` → `npm run typecheck` → `npm test` → `npm run build` → `npm run smoke -- <リポジトリ外のフォルダ>` がすべて成功することを、新しくクローンした状態で確認しています。

| 確認 | 内容 |
|---|---|
| 移行の流れ（試験用DB） | 取得ファイル読込→計画→試験用DB投入→再投入→全予定行の内容照合。失敗時は全体を取り消す |
| 本番の L Harness への投入 | D1 と同じ入口の SQLite（稼働中のアカウント・元からいる友だちとタグあり）で、投入→全予定行の照合（少しずつ読み出す）・再投入で内容が変わらないこと・途中で止めて続きから流すこと |
| 移行し直し | L Harness で有効にしたシナリオを止めないこと、有効にした後の進行を上書きしないこと、有効にしたシナリオに新しく入る人を一時停止で入れ、そのシナリオの設定・ステップを足しも書き換えもしないこと（Lステップで消したステップが残っていれば知らせること）、前に移したチャットの未読・メモを残すこと、計画の後にシナリオが有効にされたら止めること、Lステップで止めた人を一時停止にすること、何度流しても中身が変わらないこと |
| 移行し直し（続き） | Lステップで登録し直した人（開始日時が変わる）の進行状態を揃えること。L Harness 自身が作った進行状態（UUID v4・未完了）がある組には入れず、計画の後にできていれば投入前に止めること。対応ステータスが変わったら前のステータスのタグを外し、ツールが書いた「対応ステータス: …」1行だけのメモを書き換えること。既存の行の更新日時を巻き戻さないこと。1シナリオ分の退避→入れ直し→削除を同じ SQL ファイルに入れること |
| 取得できなかったもの | 管理画面で中身を取れなかったシナリオ・フォームを「空」として入れず、移行先に前から入っているステップ・設問を変えないこと。`connect` で導入フォルダと違う移行先を指定したときに導入フォルダの値を混ぜないこと、URL の先の L Harness に選んだアカウントが無ければ知らせること |
| 移行し直し（L Harness 側の変更を残す） | L Harness 側で同じ名前の友だち情報を直していれば残し、このツールが入れたままなら Lステップの新しい値にすること。チャットのメモは、このツールが書いた文そのものだけ書き換え、人が書き足した文は残すこと。取得し直して古い会話が増えても、前に入れた会話の ID が変わらず二重にならないこと。停止中のシナリオは、Lステップで消した・間に足したステップを移行先にも反映すること（並びの重なりで止まらない）。フォームの回答数を、L Harness が受けた回答も含めて数え直すこと |
| 本番で止める場面 | 計画の後に友だち・同じ名前のタグが増えた、移す友だちが別のアカウントにいる、表の列が足りない、移行先アカウントが無い、前回より古い取得結果、試験用DB向けの計画との取り違え、別のデータベース向けの計画。いずれも本番に書き込まずに止まること |
| 元からいる友だち | 同じ ID を使い、表示名・アイコン・L Harness 側のメタデータ・登録日時・チャットの状態とメモを変えずにタグ・会話・情報を足すこと。追加日は古い方、チャットの最終日時は新しい方にすること。同じ名前のタグは作らずに使うこと。L Harness が自分で記録した同じ会話は二重に入れず、ほかの会話の ID は変えないこと |
| wrangler 経由の D1 | remote / local の切り替え、一時的な失敗の再試行、エラー文に SQL の値を出さないこと、出力の受け取りの切れ目で日本語・絵文字が壊れないこと |
| connect | 導入フォルダからの読み込み、アカウントの選び方、API キーの確認、秘密を設定ファイルに書かないこと、`.env` に空の欄だけ足すこと |
| bridge | 動いている自動の送信があれば配備しないこと、秘密を引数でなく標準入力で渡すこと、転送先 URL を本人だけが読めるファイルに出すこと、フォルダごとに別の Worker 名にすること、別の移行先向けのフォルダで配備し直さないこと、トークンを入れ替えて漏れた URL を無効にすること、重複排除の設定を引き継ぐこと、Windows では動かさないこと |
| ブリッジの Worker | 署名の付け直し・replyToken を外すこと・署名の検証・トークン違いと署名違いを断ること・古い出来事を捨てること・重複排除・L Harness へ渡せなければ 502 を返して再送できること |
| enrich・richmenu | 取り直しのページ送りと全員エラーで止まること、未取り込みのリッチメニューだけを取り込むこと、Lステップ経由のリンクを知らせること（L Harness の応答は合成） |
| 取得と計画（`migrate`） | API優先の取得・ログイン待ち・Chromeを閉じた場合・待ち時間切れ・中止・移行先の事前確認（試験用DB・本番とも）・計画の作成（投入はしない）・要約に個人データを出さないこと |
| 公式API | 公式仕様に沿った合成応答で、全ページ取得・中止・再試行・システム通知の除外を確認 |

## 試験用の Cloudflare D1 での投入（2026-10-27・架空データ）

本番ではない試験用の D1 を Cloudflare に新しく作り、L Harness のスキーマと、稼働中のアカウント・元からいる友だち2人（うち1人は移行する人と同じ LINE ユーザーID）・同じ名前のタグを入れて行いました。データはすべて架空です。

| 確認 | 結果 |
|---|---|
| connect | D1 を読み、アカウントを自動で選んで保存。書き込みなし |
| 計画 | 架空の友だち402人・会話3,205件。元からいる1人を同じ ID で使い、同じ名前のタグを使い回す計画 |
| 投入・照合 | 23ファイルを投入し、4,824行・11テーブルを照合。不一致0（約100秒）。D1 Time Travel のしおりを取得 |
| 中身の独立確認 | 元からいる人の表示名・アイコンは変わらず、Lステップの情報だけ追加。関係ない友だちは残る。同じ名前のタグは1つのまま。移したシナリオは停止のまま。移行記録は「完了」 |
| 照合の繰り返し・再投入 | 照合を5回続けて一致。同じ計画の再投入は全ファイルを「流し済み」として飛ばす |
